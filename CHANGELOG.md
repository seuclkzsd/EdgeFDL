# Changelog

All user-visible changes to EdgeFDL are recorded in this file. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

## [0.2.0] - 2026-10-31

EdgeFDL can now be pointed at a real network, read-only, and its accuracy is measured on a real protocol stack and against
the methods behind existing tools. The released model `results/model.pt` and the result files of 0.1.2 are unchanged, and
0.2.0 reproduces them: `results/eval_test.json` byte for byte, and the 72-hour-equivalent self-test and the robustness suite
with the same outcomes (latency, CPU, memory and run time vary with the machine's load).

### Added

- `live` backend: `serve --backend live` measures a real routed network read-only from the EMS, with ping and a rotating
  traceroute budget (`--trace-per-round`) that respects router ICMP rate limits. Nothing is created or changed, injection
  is refused by the backend and the API, and the dashboard hides the panel.
- `preflight` command: address answers, traceroute privileges, path comparison, LSDB command, probe endpoints.
- Optional inputs `--lsdb-cmd` (FRR `show ip ospf database router json`) and `--endpoints` (YAML); `--infer-state` derives
  link and cost state from ping and traceroute; `--skip-silent`; `serve --baseline`; `baseline --backend live`.
- Engine capability queries: actions that cannot be measured are masked, and missing measurements are never read as
  failures.
- `python -m edgefdl compare`: measured comparison of the online engine with re-implementations of threshold alerting,
  alarm grouping, boolean tomography, greedy set cover, NetBouncer-style regression and 007-style voting on the same
  measurement stream, default and tuned. Results in `results/compare.json` and `docs/comparison.md`.
- `scripts/realstack_eval.py` and `scripts/realstack_run.sh`: online accuracy of the engine on the real protocol stack
  (netns, FRR OSPF, tc, wall-clock 5 s rounds), one container per shard. Results in `results/realstack.json` and
  `results/realstack/`, reported in docs/results.md, section 3.1.
- `scripts/live_blackbox.py`, `scripts/live_missing.py`: black-box validation of the `live` backend and the cost of each
  missing input.
- `docker compose up` runs the dashboard on the simulation backend with the bundled model: base image pinned by digest,
  CPU-only PyTorch, non-root, read-only root file system, no capabilities, healthcheck.
- `requirements-lock.txt` with exact versions and hashes for Python 3.12 on linux/amd64, regenerated by `tools/dev/lock.py`.
- `docs/dependencies.md`: every runtime dependency with version and license, native libraries inside the wheels, external
  programs and the distribution boundary. `tools/dev/licenses.py` fails on an unknown or strong-copyleft license.
- Recorded dashboard replay: `tools/demo/record.py` records the REST responses of a real `edgefdl serve` run into
  `docs/demo/frames.json`; `docs/demo/` replays them in the unchanged dashboard page, and `.github/workflows/pages.yml`
  publishes the static site.
- CI: `tools/dev/ci.sh` steps `image`, `deps`, `lint` and `coverage`; an `image` job; Dependabot for actions and pip; CodeQL.
- `.github/labels.yml` with `tools/dev/labels.py` and a manual workflow; `SUPPORT.md`; first contributions in
  CONTRIBUTING.md.
- `scripts/lab.sh build-torch`, or `EDGEFDL_LAB_TORCH=1 scripts/lab.sh build`, builds the lab image with CPU PyTorch; the
  default image contents are unchanged. `scripts/lab.sh` accepts `EDGEFDL_LAB_NAME` and `EDGEFDL_LAB_CPUSET`.

### Changed

- NOTICE lists the transitive packages and the container image, and records traceroute as GPL-2.0-or-later.
- `learn_baseline` paces itself at the measurement interval on the `live` backend.
- Three unused imports removed; no change in behaviour.

### Fixed

- Packet-train bandwidth estimate: a train that arrives out of order is not trusted. Per-packet jitter much larger than
  the serialization time could otherwise give an estimate of about 11 Mbps on a 1 Gbps link. Simulator results do not
  change.
- `parse_lsdb` reads broadcast OSPF networks.
- The message for a missing default topology gives advice that also works with an installed package: name a
  topology file, or run `python -m edgefdl` from the checkout.

## [0.1.2] - 2026-10-31

Patch release for packaging and documentation. No code of the engine, the training or the evaluation changed, and the
released model `results/model.pt` and the result files in `results/` are those of 0.1.1: with 0.1.2 `results/eval_test.json`
reproduces byte for byte, and the 72-hour-equivalent self-test and the robustness suite give the same outcomes (latency,
CPU, memory and run time vary with the machine's load).

### Fixed

- `edgefdl topo`, `baseline`, `gen`, `train`, `vnet` and `pipeline`, run from an installed package outside the checkout
  without a topology file, stop with a clear message instead of a `FileNotFoundError` traceback.
- The source distribution contains `configs/`, which the default `--topo` and the tests read.
- Comments and help texts no longer refer to documents that do not exist.

### Changed

- The release notes list the demo video among the assets.
- The suite has 72 tests.

## [0.1.1] - 2026-10-31

Patch release with fixes to the online engine, the REST API, the real-stack tooling and the documentation, and a
hardened API. The released model `results/model.pt` and the result files in `results/` are unchanged: with 0.1.1 the
test-set evaluations and the baseline reproduce byte for byte, the 72-hour-equivalent self-test gives the same
detector triggers, filtered anomalies, false alarms (0) and the same outcome in all 84 online scenarios, and the
robustness suite reproduces `results/robust.json` apart from its run time.

### Fixed

- **Alarm delivery.** An alarm is registered (dashboard, API, `/metrics`) before it is written to `alarm_log.csv`
  and sent to the sinks. A failing CSV write or sink no longer stops an alarm from being raised or cleared: it adds 1
  to `errors` in `/api/status`, prints `告警 <id> raise|clear 写入/外发失败（<sink>）：<error>` to standard error,
  and the other sinks still receive the record. Failed background Webhook deliveries are printed
  (`Webhook 投递失败（<url>）：<error>`).
- **Remediation rehearsal** runs on the current state of the network: links of the other active alarms count as down
  (all links of a device that is down), a drifted link keeps its LSDB cost, and a detour over another alarmed,
  degraded link is reported (for a degradation it makes the detour infeasible). The advice of all active alarms is
  rehearsed again when the set of alarms changes, and the detail then ends with `（已计入其他活动告警：…）`.
  - Link down: hosts cut off by the link count as lost, so the host access links L11–L14 are infeasible; the link's
    own NQA probe no longer counts, so the backup link L3 is feasible.
  - Degradation of a link that no monitored path crosses (L3, L8, L9, L10 on the demo topology) is rehearsed on the
    traffic between its two end devices and reports the backup path.
  - Route drift compares the paths under the current LSDB cost with the paths after restoring the baseline; it is
    infeasible when the LSDB already shows the baseline cost or no cost is known.
- **Values that were not measured** (for example the RTT of a deep probe without replies) appear as `null` in the
  alarm evidence. API responses, Webhook bodies and the `evidence` column of `alarm_log.csv` never contain `NaN` or
  `Infinity`. A forward pass with non-finite Q-values treats those actions as masked.
- **`POST /api/inject`** checks the request and returns 400 with a message for missing fields, unknown types and links
  (`未知链路 L99`), non-numeric, non-finite and out-of-range values (delay and jitter 0–10,000 ms, loss and
  bandwidth 0–1, route drift up to an OSPF cost of 65,535). `POST /api/clear` refuses unknown links (400) instead of
  succeeding silently. `GET /api/alarms?n=` with a value that is not a non-negative integer returns 400 instead of
  500. `alarms_total` and `edgefdl_alarms_total` count only alarms actually raised; if the advice cannot be built,
  the alarm is still raised (`处置建议生成失败`) and `errors` grows by 1.
- **Alarm IDs** are unique across runs and across engines started in the same second (new format, see Changed).
- **`intake -o` and `topo -o`** create the output directory, so the first command of the deployment page works in a
  fresh clone.
- **Sample generation** gives the same data set for a seed with any `--workers` value, including `--workers 1` and
  `gen --raw-csv`; the real-stack backends use the same chunked seeding.
- **Training** draws weight initialisation, exploration and replay sampling from generators seeded with the
  configured seed: the same training set, seed and thread count give the same model.
- **`vnet --dry-run`** prints the command sequence of `up` or `down` for both `netns` and `lxd` and runs nothing (it
  printed only a status for `lxd` and was ignored for `netns`). `vnet --backend lxd` runs as a dry run on a machine
  without `lxc`; the other commands of the `lxd` backend stop with a clear message there.
- **LXD backend:** the FRR files are generated in a temporary directory that is removed afterwards; device names can
  no longer place files outside it; `python -m edgefdl.vnet.lxd --uplink` refuses devices that are not in the
  topology.
- **Topology loading** refuses invalid or duplicate device names, link IDs, interface names and addresses, links from
  a device to itself and out-of-range link values, instead of silently building a different topology; automatic
  planning skips loopbacks, interface names and link IDs that the file already uses. The real-stack backends check
  Linux interface names before creating anything.
- **Intake:** PDF files are no longer sent to the multimodal endpoint, which accepts images only; they are skipped
  with a warning (convert their pages to PNG first). A drawing whose extraction fails is skipped with a warning
  instead of aborting the intake.
- **`scripts/lab.sh run`** hands files created in the repository back to the calling user and warns about output
  paths under the container's `/tmp`, which is removed with the container.
- **Log rotation** no longer overwrites an archive rotated in the same microsecond.
- **Dashboard:** the inference tile reads 单次前向推理 p99 (one forward pass), an unreachable target shows
  `RTT 不可达` without a unit, alternative conclusions use the Chinese fault-type labels, and the clear button shows
  the server's error.
- **Release workflow:** a run started by hand is always a dry run, also on a tag.
- **Tests:** the multi-alarm engine tests run on CI with `results/model.pt` instead of being skipped, and the CI
  `tests` step fails if a test is skipped because the model is missing.
- **Documentation:** route drift applies to router–router links only; the L6 example shows H3C Comware commands;
  the real-stack baseline is written inside the repository; the robustness suite takes about 3.5 minutes with 40
  workers; the ICMP rate-limiting limitation names the observed errors; packet trains and deep probes run between
  link ends; the integration example binds to a management address with `--no-inject`; the results-regeneration
  recipe keeps the 72-hour self-test; `online.long` keys in `results/README.md`; `/api/status` `infer`,
  `edgefdl_infer_ms` and the alarm's `infer_ms` are per forward pass; the `evident` clearing rule; the NumPy engine
  still needs PyTorch to load the bundle; the PyTorch build of the measurements (2.9.1, CUDA 12.8 build run on the
  CPU); the LXD licence in NOTICE.

### Security

- **Cross-site requests and DNS rebinding.** `POST` requests need `Content-Type: application/json` (415 otherwise);
  a `POST` whose `Origin` differs from its `Host` is refused (403); while `serve` listens on a loopback address it
  answers only requests addressed to `localhost`, `127.0.0.1`, `::1` or the bound address (403 otherwise). Request
  bodies are limited to 65,536 bytes (413). The dashboard sends JSON requests.
- **Model bundles** are loaded with `torch.load(..., weights_only=True)`, so loading a bundle runs no code from it.
- **CSV logs:** text cells that a spreadsheet would read as a formula (starting with `=`, `+`, `-`, `@`, tab or carriage
  return) are written with a leading `'`.
- **Topology identifiers** are restricted to safe characters, and the FRR configuration generator refuses fields with
  line breaks or control characters, so topology fields cannot add configuration lines or reach other paths.
- **Vulnerability reports:** [SECURITY.md](SECURITY.md) gives a reporting path that works while GitHub's private
  vulnerability reporting is not yet available.

### Changed

- PyTorch 2.0 or newer is required (`requirements.txt`, `pyproject.toml`), for `weights_only=True` loading.
- Alarm IDs have the form `A<Unix start time>-<6 random hex digits>-<4-digit sequence>`, for example
  `A1793328137-fdd818-0001` (previously `A<7 digits>-<4 digits>`).
- `serve --sinks` is checked at start: a Webhook needs a complete `http://` or `https://` URL, a Syslog sink a `host`
  and a port from 1 to 65535; unknown types are an error instead of being ignored; a single JSON object is accepted
  as well as a list. An invalid configuration stops `serve` before the network backend comes up, with exit code 1 and
  `edgefdl: --sinks 配置有误：<reason>`.
- GOVERNANCE.md: a release may keep the `results/` files of an earlier release when it reproduces them, as 0.1.1
  does.
- The README title gives the project name, EdgeFDL — Edge-network Fault Detection and Localization.
- `edgefdl topo` names blind links as `盲区链路（已规划 NQA 探测目标）`: the NQA probe is planned by EdgeFDL and
  configured by the operator on the device.
- `curl` and other clients have to send `-H 'Content-Type: application/json'` with `POST /api/inject` and
  `/api/clear`.

### Added

- [results/sim_vs_stack.json](results/sim_vs_stack.json) and [scripts/sim_vs_stack.py](scripts/sim_vs_stack.py):
  per-target baseline RTT of the demo network on the real protocol stack and on the simulator; all 37 targets agree
  within 0.74 ms (median 0.39 ms).
- `python -m edgefdl.vnet.lxd --stage-dir DIR` keeps the generated FRR files for review.
- [tests/test_engine.py](tests/test_engine.py) (sinks, JSON encoding, API validation and cross-site checks,
  rehearsal) and [tests/test_infra.py](tests/test_infra.py) (topology validation, dry runs, CSV logs,
  reproducibility, bundle loading, intake); the suite has 71 tests.
- The demo video `EdgeFDL-demo-zh.mp4` (Chinese narration, 6 min 41 s) is attached to the
  [v0.1.1 release](https://github.com/seuclkzsd/EdgeFDL/releases/tag/v0.1.1).

## 0.1.0 - 2026-10-30

Not published as a release; its changes ship in 0.1.1.

First version of EdgeFDL: autonomous link-level fault detection and localization for edge networks, running on the
network-management server (EMS).

### Added

- **Requirements intake** (`python -m edgefdl intake`): a form template
  ([configs/intake_demo/form.yaml](configs/intake_demo/form.yaml)), extraction of interfaces, addresses, OSPF costs
  and speeds from Huawei, H3C and Cisco configuration text, LLDP neighbour tables, and an optional OpenAI-compatible
  multimodal endpoint (`--llm`) for topology images and PDFs.
- **Topology model** (`edgefdl/topology.py`): automatic IP and loopback planning, OSPF shortest paths, monitored
  targets, and coverage planning that adds a device-native NQA / IP SLA probe for links that no monitored path
  crosses. Demo topology [configs/demo_topology.yaml](configs/demo_topology.yaml): 12 devices, 15 links.
- **Equivalent virtual network** with three interchangeable backends and the same fault semantics: `sim` (analytic
  simulator), `netns` (Linux network namespaces, FRR OSPF, `tc`) and `lxd` (one container per device, optional
  bridged uplink; `python -m edgefdl.vnet.lxd ... --uplink` prints the deployment command sequence).
  `python -m edgefdl vnet up|down|status` manages the real-stack backends.
- **Fault model and injector**: link down, delay, loss, jitter, bandwidth degradation (`tbf`) and route drift (OSPF
  cost change that moves a monitored path), applied at both link ends; 231 fault primitives on the demo topology.
- **Sample generation** (`python -m edgefdl baseline`, `gen`): baseline learning, trigger-aligned samples cut where
  the online detector wakes the agent, domain randomization (transient length, ICMP rate limiting, background
  jitter), `--plain` for standard-condition test sets, multi-process generation.
- **DDQN agent** (`python -m edgefdl train`, `eval`): Double DQN with a dueling head, a link-shared encoder,
  prioritized replay, action masking and a deep-probe action with a per-probe cost in the reward; 36,041
  parameters; PyTorch and NumPy inference engines (`serve --engine numpy`). Model bundles are single files
  containing weights, topology, baseline and measurement plan.
- **Online engine** (`python -m edgefdl serve`): 5 s light measurement rounds (ping, traceroute, packet-train
  bandwidth estimates, OSPF LSDB), k-of-n detector, diagnosis with on-demand deep probes, confirmation, one alarm
  per fault with evidence, device-down aggregation, concurrent multi-fault alarms through residual re-baselining
  (`--single-alarm` keeps one alarm at a time), per-alarm recovery, on-site baseline learning
  (`--learn-rounds`), RTT baseline tracking and background-loss re-learning.
- **Remediation advice**: troubleshooting and remediation commands for Huawei VRP, H3C Comware and Linux/FRR, with
  temporary actions rehearsed on the equivalent topology so that only feasible actions are recommended.
- **Integrations**: Web dashboard (Chinese UI) at `http://127.0.0.1:8460`, REST API (`/api/topology`, `/api/status`,
  `/api/alarms`, `/api/series`, `/api/export/*.csv`, `POST /api/inject` and `/api/clear` for virtual backends,
  `--no-inject` to disable them), Prometheus `/metrics`, Syslog (RFC 5424) and Webhook (JSON) sinks (`--sinks`).
- **Logs**: `measure_log.csv` and `alarm_log.csv` with `schema_version` and `*.schema.json`, flushed per line,
  synced to disk every 5 s, rotated at 200 MB.
- **Evaluation tools**: `python -m edgefdl pipeline` (baseline, samples, training, evaluation and self-test in one
  command), `bench` (inference latency, overhead, long-run false alarms, online scenarios), `robust` (harsh
  conditions, measurement defects, fault-size sweep, concurrent faults and device failures; `--seed`, `--kinds`,
  `--only`, `--single-alarm`), and [scripts/compare_robust.py](scripts/compare_robust.py) for pass criteria of the
  multi-alarm engine against the single-alarm mode.
- **Real-stack lab**: [scripts/lab.sh](scripts/lab.sh) and [scripts/lab/Dockerfile](scripts/lab/Dockerfile)
  (Debian 12 with FRR, iperf3, traceroute, iproute2) and [scripts/netns_smoke.py](scripts/netns_smoke.py) with 26
  checks of fault semantics on the real protocol stack.
- **Released model and results** in [results/](results/README.md): `model.pt`, `baseline.json`, `eval_test.json`,
  `eval_test_rand.json`, `bench.json`, `robust.json`, `pipeline.log` and real-stack smoke logs. On the independent
  test set (10,000 samples, standard conditions, simulation backend, demo topology), type + location accuracy is
  100.00% for link down, 98.73% for performance degradation and 100.00% for route drift; one forward pass takes
  0.575 ms at p99 (PyTorch, 1 thread). Details and conditions: [docs/results.md](docs/results.md).
- **Documentation**: [README.md](README.md) (English) and [README.zh-CN.md](README.zh-CN.md), quick start,
  deployment, API, architecture, algorithms, results and comparison pages under [docs/](docs/index.md).
- **Project infrastructure**: Apache-2.0 [LICENSE](LICENSE) and [NOTICE](NOTICE), SPDX headers checked by
  `tools/dev/spdx.py`, [CONTRIBUTING.md](CONTRIBUTING.md), [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) (Contributor
  Covenant 2.1), [SECURITY.md](SECURITY.md) with a data handling statement, [GOVERNANCE.md](GOVERNANCE.md),
  [MAINTAINERS.md](MAINTAINERS.md), [ROADMAP.md](ROADMAP.md), [CITATION.cff](CITATION.cff), issue forms (bug report,
  feature request, report from a real network) and a pull request template, a CI workflow running
  `tools/dev/ci.sh`, a release workflow, and 34 unit tests.
